In traditional developer tooling, connecting an AI coding agent to a new backend service requires a frustrating ritual:
1. Open `.cursor/mcp.json` or `claude_desktop_config.json`.
2. Add a new JSON configuration block with command paths and API keys.
3. Completely **restart the IDE or chat session**, dumping all active context, open tabs, and scratchpad memory.
4. Re-prompt the agent from scratch.

This friction completely breaks developer flow. If your agent is halfway through diagnosing a production outage and realizes it needs access to a staging database or internal Sentry server, asking the human to restart the editor is an anti-pattern.

Spike Land eliminates this friction entirely with **Zero-Restart Mid-Chat MCP Server Mounting**.

---

## 1. The Anatomy of Mid-Chat Mounting

With Spike Land, your AI agent connects new servers autonomously using the `mount_mcp_server` broker tool. As far as Cursor, Windsurf, or Claude Desktop are concerned, **the client tool list never changes**. Spike Land performs all connection discovery, token authentication, and schema namespace routing at the Cloudflare edge.

Here is the three-step flow:

<MountMidChat highlightStep={1} />

### Step 1: The Agent Mounts the Server In-Band
When the user says:
> *"Check the schema of the orders table in our staging Postgres MCP server at https://db-mcp.internal.example.com/mcp"*,

The agent invokes Spike Land's built-in `mount_mcp_server` tool:
```json
{
  "name": "mount_mcp_server",
  "arguments": {
    "server_url": "https://db-mcp.internal.example.com/mcp",
    "prefix": "pg",
    "auth_token_vault_id": "vault_pg_staging"
  }
}
```

### Step 2: Edge Handshake & Schema Virtualization
Spike Land's Cloudflare Worker receives the request, connects to the remote MCP server via HTTP/SSE, validates protocol compatibility (MCP 2026-07-28), and registers the tools under the `pg.*` namespace in the session's ephemeral KV store.

Crucially, **the upstream IDE receives a standard JSON response turn**. No WebSocket reconnects. No editor reboots.

### Step 3: Immediate Execution
In the very next turn, the agent inspects or runs the newly mounted tool:
```json
{
  "name": "execute_tool",
  "arguments": {
    "tool_name": "pg.describe_table",
    "arguments": { "table": "orders" }
  }
}
```

Spike Land looks up the `pg` prefix, fetches the staging database token securely from Cloudflare Secrets Store, forwards the JSON-RPC execution, and streams the result back to the LLM. The model never sees the raw credential.

## 3. Security & Sandboxing at Cloudflare Edge

Mounting external MCP servers mid-session introduces security requirements that local desktop proxies cannot safely handle. Spike Land solves these at the edge layer:

<Callout type="warning" title="SSRF & Private Network Isolation">
Spike Land enforces strict Server-Side Request Forgery (SSRF) filters. External requests to cloud metadata endpoints (<code>169.254.169.254</code>) or internal loopback interfaces (<code>127.0.0.1</code>) are blocked by default unless explicitly whitelisted via authenticated Cloudflare Tunnel bindings.
</Callout>

1. **Credential Vault Separation:** Authentication tokens for remote MCP servers are stored in encrypted KV isolates. Neither the LLM prompt nor the client IDE ever sees plaintext database credentials.
2. **Namespace Collision Defense:** Every mounted server is assigned a dedicated namespace prefix (e.g. `pg.*`, `sentry.*`, `stripe.*`), preventing hostile servers from shadowing or overriding critical core tools.
3. **Session Ephemerality:** Mid-chat mounted servers exist solely for the lifetime of that conversation session unless explicitly pinned to a workspace team profile.

## 4. Architectural Comparison

| Dimension | Standard MCP (Desktop JSON) | Spike Land Mid-Chat Mount |
| :--- | :--- | :--- |
| **Connection Timing** | Boot-time static | Runtime mid-conversation |
| **IDE Restart Required?** | **Yes (Every change)** | **Never** |
| **Credential Storage** | Plaintext in local disk files | Cloudflare Secrets Store & Vault |
| **Cache Hit Impact** | Busts prompt cache on reload | 0% cache invalidation |
| **Latency to First Call** | 15–30 seconds (relaunch) | < 120ms (Edge connection) |

By treating MCP servers as dynamic capabilities that agents can summon on-demand rather than static desktop configuration files, Spike Land makes agentic development truly continuous.
