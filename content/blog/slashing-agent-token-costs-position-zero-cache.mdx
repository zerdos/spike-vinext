## 1. The Geometry of LLM Prefix Caching

State-of-the-art frontier models rely on Key-Value (KV) prompt caching to accelerate inference and slash input token pricing. Both Anthropic (Prompt Caching) and OpenAI (Automatic Prompt Caching) divide input prompts into sequential token chunks:

```text
[Position 0: System Prompt & Tools] -> [Turn 1: User] -> [Turn 1: Assistant] -> [Turn 2: User]
```

When an incoming prompt shares an identical prefix with a cached sequence:
- **Cache Hit Pricing:** Anthropic charges only $0.30 per million tokens (a 90% discount over standard input tokens).
- **Latency Advantage:** Time-to-First-Token (TTFT) drops from ~1,800ms to < 220ms.

<Callout type="warning" title="The Position-Zero Invariant">
Prefix caching operates strictly from left to right starting at <strong>Token Position 0</strong>. If even a single character, whitespace, or tool definition changes at Token Position 0, the entire downstream KV cache is invalidated.
</Callout>

### The Naive MCP Proxy Trap

Consider a developer using an MCP proxy with 455 available tools across 9 categories. In naive setups, one of two catastrophic failure modes occurs:

1. **The Monster Tool Block (Brute Force):**
   The client dumps all 455 JSON-RPC tool schemas into the system prompt upfront. At an average of 110 tokens per schema, the agent pays a fixed overhead of **50,050 tokens on every single turn**. Even with 50-turn sessions, context windows fill instantly, and costs spiral past $1,200/month per developer.
2. **Dynamic Tool Mutation (Pattern A):**
   To avoid paying 50,050 tokens upfront, naive proxies dynamically rewrite `tools/list` when users switch domains (e.g. from git to postgres). But mutating `tools/list` changes the prefix at **Token Position Zero**. The model's 60,000-token conversation history cache is completely destroyed, incurring a massive re-read penalty.

## 3. How Spike Land Preserves Position Zero

Spike Land solves this fundamental tension through **Two-Sided Progressive Disclosure** (SEP-2567). Instead of pushing hundreds of changing tool schemas into the model's primary prompt, Spike Land exposes only **five static broker meta-tools** at Token Position Zero:

| Broker Meta-Tool | Tokens | Purpose |
| :--- | :--- | :--- |
| `list_capability_categories` | 85 | Lists active and available tool categories without exposing raw schemas |
| `configure_active_categories` | 92 | Activates capability domains in-band |
| `inspect_tool_schema` | 104 | Retrieves exact parameter schemas on-demand |
| `execute_tool` | 128 | Executes any tool across 455 catalog endpoints |
| `inspect_result_slice` | 98 | Streams large outputs with pagination |

Because these five broker meta-tools **never change signature or order**, Token Position Zero remains 100% immutable across every turn, session, and project.

```text
Turn 1: [5 Static Broker Tools (507 tokens)] [Chat History (2,000)]
Turn 2: [5 Static Broker Tools (507 tokens)] [Chat History (4,500)] <-- 100% CACHE HIT
Turn 3: [5 Static Broker Tools (507 tokens)] [Chat History (7,200)] <-- 100% CACHE HIT
```

### Tail Disclosure: Working Sets in Recent Turns

When the agent needs to call a specific tool (e.g. `pg.query_db`), it fetches the schema via `inspect_tool_schema`. That schema is returned **in the user/tool response turn at the tail of the context window**, rather than prepended to Position Zero.

The upstream prefix remains cached; only the incremental tail turn is evaluated.
